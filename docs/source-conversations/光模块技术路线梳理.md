### GPT

<!-- message:2acb2eb8-6893-4533-b08c-4686ccb7116b:start -->
可以。你现在要做的不是单纯“列出 EML、硅光、LPO、CPO”，而是建立一棵**能够持续往 800G → 1.6T → 3.2T 推演的技术树**。因为这些词其实不在同一个维度：**EML/硅光是光引擎路线，DSP/LPO 是电信号处理架构，Pluggable/CPO 是封装位置，DR/FR 又是传输规格。**混在一起比较一定会乱。

我建议按下面这套框架梳理。

### 第一层：先固定“光模块到底要完成什么”

最基本的链条是：

**Switch / GPU SerDes → Electrical Interface → DSP / Retimer → Driver → 光源 + 调制 → 光波导/复用 → Fiber → 解复用 → PD → TIA → DSP → SerDes**

然后所有技术路线都挂在这条链上。

你真正研究的是：

> 随着单通道从 **100G/lane → 200G/lane → 400G/lane**，哪些环节开始成为瓶颈，因此产生什么替代路线？

这比从“800G有哪些路线”开始更容易理解产业变化。

---

## 第二层：把技术路线拆成 5 个彼此独立的维度

| 维度 | 主要路线 | 你需要研究的问题 |
|---|---|---|
| **光源/调制** | EML / CW Laser + SiPh / VCSEL / TFLN 等 | 谁负责产生光、谁负责调制？速率上限？功耗？成本？ |
| **光子集成** | Discrete / InP PIC / Silicon Photonics | 调制器、波导、MUX、耦合能不能集成？ |
| **电处理架构** | DSP / TRO / LRO / LPO | DSP放在哪里？能不能减少/取消？ |
| **封装形态** | Pluggable / NPO / CPO | 光引擎离交换ASIC多远？电通道损耗多少？ |
| **传输结构** | SR/DR/FR/LR；parallel / WDM | 多远距离？几根fiber？多少波长？ |

**这五层不要混。**

比如：

> **1.6T SiPh LPO OSFP DR8**

实际上描述的是：

- 速率：1.6T
- 光子平台：Silicon Photonics
- 电架构：LPO
- 封装：Pluggable OSFP
- optical interface：DR8

而不是一种单独的“技术路线”。

Marvell已经展示了 **1.6T silicon-photonics light engine + LPO reference module，200G/lane**，就是一个很好的真实案例。citeturn124659search11turn124659search22

# 第三层：重点研究“光引擎路线”

这里我建议你先只抓四条：

### 路线 A：EML

大致：

**Laser + EAM modulation → coupling → fiber**

优势：

- 技术成熟
- 高带宽
- 较好的信号质量
- 产业链成熟
- 800G已经大量使用

而且它并没有因为硅光出现就马上消失。

Lumentum目前明确表示，100G/200G EML用于400G/800G，并继续向1.6T演进；2026年又展示了**400G differential EML**构建1.6T DR4原型。citeturn124659search6turn124659search1

所以你的技术树应该画成：

**100G EML → 200G EML → 400G D-EML**

而不是：

**800G EML → 1.6T SiPh**

这两个不是严格的代际替代关系。

---

### 路线 B：Silicon Photonics

典型：

**CW Laser → SiPh Modulator → Waveguide → MUX → Fiber**

这里最重要的理解是：

**SiPh本身通常不是激光器。**

所以硅光路线仍然需要：

**CW laser**

例如 Lumentum 现在明确把CW laser定位给 **SiPh transceiver和CPO**使用。citeturn124659search5turn124659search20

硅光真正解决的是：

> 把 modulator / waveguide / MUX / coupling 等越来越多光学功能集成到PIC上。

这也是你之前觉得“硅光像封装”的原因——你的感觉并不完全错，因为它的价值很大一部分确实来自**光学集成**。

但严格来说：

> **SiPh = 光子集成平台**
>
> **CPO = 系统封装架构**

完全不是一个维度。

---

### 路线 C：VCSEL

尤其重要的是短距离。

可以重点研究：

**VCSEL + multimode fiber**

现在AI scale-up网络又让VCSEL重新变得值得研究。Lumentum 2026年就特别提到所谓 **slow-and-wide** 架构：不用把每lane拼命推到极高速度，而是使用更多较低速parallel optical lanes，以降低整体SerDes压力。citeturn124659search19

所以未来未必只有：

> 100G → 200G → 400G/lane

还有另一条：

> **更多lane × 较低lane rate**

这是很重要的一条产业分叉。

---

### 路线 D：InP PIC / 新型调制器

这里先放第二优先级。

包括：

- InP integrated photonics
- TFLN
- micro-ring
- electro-optic polymer 等

先不要陷得太深。

你的第一阶段核心还是：

**EML vs SiPh**

---

# 第四层：单独研究 DSP 路线

这部分是理解未来光模块最关键的东西之一。

传统：

**Switch ASIC → DSP → Driver → Optical Engine**

DSP作用包括：

- gearbox
- equalization
- FEC相关处理
- retiming
- signal conditioning

问题是：

> lane rate越高，DSP功耗越大。

于是产生：

### DSP-based optics

现在最成熟。

Marvell目前的1.6T DSP仍然是800G/1.6T pluggable的重要方案。citeturn124659search2turn124659search7

↓

### TRO

Transmit Retimed Optics

只保留部分DSP功能。

↓

### LRO

Linear Receive Optics

继续减少DSP。

↓

### LPO

Linear Pluggable Optics

尽量利用switch ASIC SerDes，减少光模块内部DSP。

所以这条技术演进其实是：

**Full DSP → partial DSP → linear optics**

解决的核心问题：

**Power + latency + cost**

但代价是：

**link margin / interoperability / signal integrity / system engineering难度**

---

# 第五层：再研究 Pluggable → CPO

这个时候你才应该引入CPO。

传统：

**ASIC ───────── PCB electrical trace ───────── Pluggable optics**

问题：

随着SerDes达到200G/400G：

**这段PCB高速电连接越来越难。**

于是：

### Pluggable

ASIC → PCB → front panel optics

↓

### NPO

ASIC → very short electrical → nearby optics

↓

### CPO

ASIC + Optical Engine 同封装

本质是：

> **把最难传输的高速电信号距离缩短。**

NVIDIA已经把这一方向产品化：其Spectrum-X Photonics把silicon-photonics optical engines与交换芯片封装整合；NVIDIA 2026年还称Spectrum-6 CPO进入量产部署阶段。citeturn124659search3turn124659search29

这里就会产生你之前一直问的那个问题：

> “几十厘米变成1厘米不就行了吗？”

其实 **NPO/CPO正是在干这件事。**

<!-- message:547265bd-a209-4fd5-963c-28abb84b11ed:end -->

### GPT

<!-- message:3a540851-5650-42a2-9278-de37d7a424ed:start -->
评价光模块，不能只看“800G/1.6T”这个总带宽。真正决定性能的指标，我建议你分成 **6 类** 来看：

| 类别 | 核心指标 | 代表什么 |
|---|---|---|
| **带宽/速率** | 总速率、lane数、单lane速率 | 模块能传多快 |
| **光学性能** | Tx Power、OMA、ER、Rx Sensitivity、功率预算 | 光信号发得多好、收得多弱还能工作 |
| **信号质量** | TDECQ、BER、FEC、Eye diagram | 信号失真和误码程度 |
| **距离** | Reach：100m / 500m / 2km / 10km | 能传多远 |
| **功耗/热** | Module Power、W/Gbps、温度范围 | AI数据中心尤其关键 |
| **物理/可靠性** | Form factor、密度、MTBF、插损 | 能否高密度部署、长期稳定运行 |

其中如果你是为了梳理 **800G → 1.6T → 3.2T 技术路线**，最重要的其实是下面这些。

### 1. 总带宽 + 单 Lane 速率

例如：

- 800G：8×100G 或 4×200G
- 1.6T：8×200G
- 未来3.2T：可能8×400G

这里**单lane速率比总带宽更值得关注**。

因为从100G/lane升到200G/lane，会直接提高对：

**EML / SiPh modulator / Driver / TIA / DSP / PCB SerDes**

的要求。

所以你看一个模块时第一句话应该问：

> **800G是8×100G还是4×200G？**

这两种800G技术含量完全不一样。

### 2. 功耗 Power

通常以：

**W / module**

表示。

比如同样1.6T：

- 方案A：20W
- 方案B：14W

这个差异非常重要。

还可以进一步算：

\[
Energy\ Efficiency=\frac{Power}{Bandwidth}
\]

比如：

\[
16W / 1.6Tbps = 10W/Tbps
\]

未来真正值得观察的是：

> **W/Tbps 是否持续下降。**

这也是LPO和CPO为什么重要：它们很大程度就是在解决高速互联功耗问题。

### 3. 传输距离 Reach

常见大概：

- SR：几十到100m级
- DR：500m级
- FR：2km
- LR：10km级

但不能简单理解成：

> 越远越好。

因为不同距离对应完全不同场景。

AI数据中心内部可能重点关注：

**100m / 500m / 2km**

而电信网络可能关注10km甚至更远。

所以比较产品的时候必须：

**同距离等级下比较性能。**

---

### 4. Tx Optical Power

即：

**发射光功率**

单位一般：

**dBm**

简单理解：

> 模块发出去的光有多强。

但并不是单纯越高越好，因为太高也可能带来receiver overload等问题。

---

### 5. Receiver Sensitivity

即：

**接收灵敏度**

比如：

- –4 dBm
- –6 dBm
- –8 dBm

通常越低越好。

意思是：

> 即使收到的光很弱，receiver还能正确识别信号。

这会直接决定系统的**power budget**。

---

### 6. Optical Power Budget

这个我认为是你研究光模块时**必须真正理解的指标**。

简单来说：

\[
Power\ Budget
=
Tx\ Minimum\ Power
-
Rx\ Sensitivity
\]

例如：

Tx minimum：

\[
-1dBm
\]

receiver sensitivity：

\[
-5dBm
\]

那么：

\[
Power Budget=4dB
\]

这4dB要覆盖：

- fiber loss
- connector loss
- coupling loss
- splitter/MUX loss
- aging
- temperature variation

所以它实际上告诉你：

> **这条光链路允许损失多少。**

你之前研究SiPh coupling，这个指标就直接相关。

---

### 7. OMA

**Optical Modulation Amplitude**

这是一个非常重要但容易被忽略的指标。

它不是简单看平均光功率，而是：

> 逻辑高电平和低电平之间实际有多少“光强差”。

对于PAM4尤其重要。

可以粗略理解：

**OMA越大 → receiver越容易区分不同level。**

因此研究：

- EML
- SiPh modulator
- VCSEL

的时候，OMA非常值得比较。

---

### 8. Extinction Ratio，ER

即：

**消光比**

本质：

\[
ER=\frac{P_1}{P_0}
\]

表示：

> “1”和“0”对应的光功率差异有多大。

ER越高一般意味着：

**on/off状态区分更明显。**

但到了PAM4不能只依赖ER，因此OMA/TDECQ等指标更加重要。

---

### 9. TDECQ

如果你研究800G以上，这个指标非常重要。

全称：

**Transmitter and Dispersion Eye Closure Quaternary**

它实际上回答：

> PAM4信号经过真实链路之后，因为噪声、失真、色散等原因，信号质量恶化了多少？

一般：

**TDECQ越低越好。**

所以看到：

- 2 dB
- 3 dB
- 4 dB

通常2dB的Tx质量更好。

这是比较：

**EML vs SiPh modulator**

时非常有用的performance metric。

---

### 10. BER

**Bit Error Rate**

比如：

\[
10^{-6}
\]

意思是一百万bit里面大约有一个error。

高速光通信里通常会看：

**Pre-FEC BER**

和：

**Post-FEC BER**

因为现在基本都会使用FEC。

因此一个模块可以：

> raw BER不特别低，但通过FEC以后满足系统要求。

---

### 11. FEC Margin

这个其实对未来200G/lane、400G/lane尤其重要。

你可以理解为：

> 信号距离FEC无法纠错的极限还有多少余量。

Margin越大：

- 系统更稳定
- 对temperature/aging更有容忍度
- production yield通常也更容易做

因此不要只问：

> 能不能跑起来？

而应该问：

> **离极限有多远？**

### 三、接收性能：多弱的信号还能收到

**Receiver Sensitivity + BER + FEC margin**

> “FEC勉强能救回来。”

> **距离 FEC threshold 还有足够 margin。**

+ Connector Loss
+ Coupling Loss
+ MUX Loss
+ Margin

\text{Power Efficiency}=\frac{\text{Module Power}}{\text{Bandwidth}}
\]

也就是每搬 1 Tbps 数据要消耗多少瓦。LPO、CPO 很大程度上就是在解决这个问题。

**3. 可靠性与信号余量**  
数据中心不是只要求“跑得起来”，而是要长期稳定。重点包括 BER、FEC margin、link availability、MTBF。规模越大，这个问题越重要：单链路极低的故障率，乘以几十万条链路以后，也可能变成持续发生的系统问题。AI 训练又很依赖大规模 collective communication，所以网络链路抖动、重传或故障会直接拖低 GPU 利用率。

**4. 成本，最好看 $/Gbps 或 TCO/Tbps**  
不能只比较一个 800G 模块多少钱、一个 1.6T 模块多少钱。更重要的是单位带宽成本，以及整个系统的总成本，包括模块、交换机、电力、散热、光纤、维护和更换成本。最终赢家不一定是实验室性能最强的路线，而可能是**够好、便宜、功耗低、量产稳定**的路线。

**5. Reach，要“刚好够用”，不是越远越好**  
数据中心不同层级需要的距离不同。机架内、机架间、数据中心园区内对应的最佳技术路线可能完全不同。一个只需要几十米的连接，没有必要为 10 km 的能力付额外成本。因此 Reach 本质上是约束条件，而不是单纯的性能排名指标。

如果再往下一层，像 **TDECQ、OMA、Rx sensitivity、ER、Pre-FEC BER** 这些指标非常重要，但它们更像“模块工程指标”。它们最终服务于上面的系统指标：

**TDECQ / OMA / Rx sensitivity / BER**  
→ 决定信号质量和链路余量  
→ 决定可靠性、距离、功耗  
→ 最终影响数据中心 TCO 和可扩展性。

所以你以后研究光模块技术路线，可以直接用这一条主线：

\[
\boxed{\text{Bandwidth / Density}}
\]

\[
\boxed{\text{W/Tbps}}
\]

\[
\boxed{\text{Reliability / Margin}}
\]

\[
\boxed{\$/Gbps}
\]

\[
\boxed{\text{Required Reach}}
\]

然后问：**从 800G → 1.6T → 3.2T，哪一个指标恶化得最快？**

这个问题会直接把你带到为什么行业会讨论 **200G/400G lane、SiPh、D-EML、LPO、CPO**。

# 为什么数据中心愿意这么干？

这里才有4个真正具体的经济原因。

### ① 少一半物理链路

如果需要100Tbps的互联能力：

800G：

\[
100/0.8=125条
\]

1.6T：

\[
100/1.6\approx63条
\]

于是：

**模块、光纤、connector、cage、patching 数量大约减半。**

这不是解决“有没有地方放”，而是在减少整个网络中的**物理对象数量**。

---

### ② 每bit功耗有机会下降

这里不能说“1.6T一定比两个800G省电”，要看具体产品。

但新一代DSP、laser、driver、TIA等可以共享很多固定overhead，因此行业目标是让：

\[
\frac{Power}{bit}
\]

下降。

Marvell曾展示其200G/lane 1.6T方案相对于上一代connectivity降低约30%的power per bit。citeturn653294search17

所以比较应该是：

\[
2\times800G\ module
\]

vs

\[
1\times1.6T\ module
\]

而不是：

> “一个1.6T比一个800G功耗高，所以1.6T没意义。”

---

### ③ 网络复杂度下降

假设两个交换机之间需要6.4T：

800G：

\[
8条link
\]

1.6T：

\[
4条link
\]

因此：

- link aggregation数量下降
- fiber数量下降
- transceiver数量下降
- failure points下降
- cable management下降

到了几十万GPU，**数量本身就是成本。**

---

### ④ 配合下一代交换芯片继续提高 radix × bandwidth

交换机能力粗略可以理解成：

\[
\boxed{Port\ Count\times Port\ Speed}
\]

例如：

\[
64\times800G=51.2T
\]

升级：

\[
64\times1.6T=102.4T
\]

注意这里最重要的是：

> **保持64个逻辑端口不变，端口速率翻倍。**

如果你坚持800G：

\[
128\times800G=102.4T
\]

当然也能得到102.4T。

**但这就意味着你把port count翻倍。**

所以产业面对的是两个选择：

\[
\boxed{64\times1.6T}
\]

vs

\[
\boxed{128\times800G}
\]

这才是我们应该讨论的问题。

假如：

**128×800G**

面板放不下。

你说：

> 做成2U不就好了？

**对，完全可以。**

所以“front panel面积”不是1.6T出现的根本原因。

即使给你无限大的面板，你仍然要比较：

128 modules  
128 cages  
128 fiber links  
128 module controllers/DSP chains

vs

### 64 × 1.6T

64 modules  
64 cages  
64 fiber links  
64 module chains

然后比较：

\[
\$/Tbps
\]

\[
W/Tbps
\]

\[
Failure/Tbps
\]

\[
Fiber/Tbps
\]

\[
Space/Tbps
\]

最终如果：

\[
1\times1.6T
<
2\times800G
\]

在系统成本上成立，**1.6T就有意义。**

# 所以我把“为什么从800G升级1.6T”重新排序

不是：

> ❌ 800G速度不够  
> ❌ 前面板放不下  
> ❌ AI必须用1.6T

而是：

> **SerDes从100G/lane → 200G/lane**
>
> ↓
>
> **单位物理链路可以从800G → 1.6T**
>
> ↓
>
> 对相同总网络容量
>
> **需要的physical links减少**
>
> ↓
>
> **模块 / cage / fiber / connector / DSP chain数量减少**
>
> ↓
>
> 同时争取
>
> **更低W/Tbps + 更低$/Tbps + 更高Tbps/RU**

所以真正驱动1.6T的公式其实是：

\[
\boxed{
\text{Higher SerDes Rate}
\rightarrow
\text{Higher Bandwidth per Physical Link}
\rightarrow
\text{Lower Infrastructure per Tbps}
}
\]

这比“AI需要更大带宽”准确得多。

而且这里会带出一个**对你做光模块产业研究非常关键的问题**：

> **1个1.6T模块，到底能不能在成本、功耗和可靠性上显著优于2个800G模块？**

如果答案是否定的，那么客户完全可以继续堆800G；如果答案变成肯定的，才是真正推动1.6T渗透的经济拐点。

↓

\boxed{DFB\ Laser + EAM}

**DFB Laser**

负责持续产生光。

**EAM（Electro-Absorption Modulator）**

负责把高速电信号编码到光上。

所以结构可以想成：

```text
Electric data

    Driver
      ↓
DFB Laser → EAM → Fiber
   发光       调光
```

实际上DFB和EAM通常集成在一块InP芯片上。

> **光源和高速调制器都已经给你做好了。**

\[
8\times200G=1.6T
\]

的模块。citeturn353753search3

# 2. SiPh：不是“一颗激光器”，而是一块光学集成芯片

这是最容易混淆的。

Silicon Photonics里面一般做的是：

- modulator
- waveguide
- splitter
- MUX/DEMUX
- coupler
- photodetector

也就是说，它更像：

> **“光学版集成电路平台”。**

比如：

```text
CW Laser
   ↓
   ┌──────────────── Silicon Photonics PIC ────────────┐
   │                                                   │
   → Waveguide → Modulator → MUX → Coupler → Fiber
   │                                                   │
   └───────────────────────────────────────────────────┘
```

注意最左边：

**CW Laser通常不是硅光芯片自己产生的。**

因为硅是indirect bandgap材料，本身并不适合高效率产生激光，所以实际产品往往还需要：

- InP CW laser
- external laser source
- 或者heterogeneous integrated laser

因此你之前说：

> “硅光是不是把光引擎封装起来？”

你的直觉有一部分来源于这里。

因为SiPh真正厉害的地方不是“有一个新的laser”，而是：

\[
\boxed{\text{把很多光学功能集成到一块PIC}}
\]

# 3. VCSEL：Laser本身直接高速开关

VCSEL：

**Vertical-Cavity Surface-Emitting Laser**

也是一个laser。

但跟传统edge-emitting laser不同，它是：

> **从wafer表面垂直向上发光。**

结构可以非常粗略地理解成：

```text
      ↑ Light
      ↑
   [ VCSEL ]
      ↑
Electrical signal
```

所以：

\[
Electric\ current
\rightarrow
VCSEL\ intensity
\]

可以直接把数据编码进去。

不一定需要像EML那样：

> Laser + 单独的EAM。

这叫：

\[
\boxed{Direct\ Modulation}
\]

因此VCSEL结构非常简单。

而且它特别容易做成array：

```text
● ● ● ● ● ● ● ●
```

8颗VCSEL：

\[
8\times100G=800G
\]

Coherent已经量产/展示用于100G PAM4 lane的VCSEL array，也已经展示200G/lane VCSEL用于1.6T transceiver。citeturn353753search8turn353753search14

# 为什么VCSEL便宜，但EML还能存在？

因为物理性能不同。

VCSEL最大的优势是：

\[
\boxed{简单 + 小 + 低功耗 + 易阵列化}
\]

但传统高速datacom VCSEL主要工作在：

\[
850nm
\]

配合：

**multimode fiber**

所以更适合短距离。

例如：

```text
GPU / Switch
     │
   VCSEL
     │
 MMF fiber
     │
几十米～百米级
```

随着lane rate提高，它的bandwidth、mode dispersion等问题越来越突出。Coherent自己就指出，传统oxide-aperture VCSEL在100G/lane时代已接近约27 GHz的带宽限制，因此需要新的VCSEL结构来继续往200G/lane推进。citeturn353753search32

# EML为什么更适合长一点的距离？

EML通常使用：

**1310nm附近 + single-mode fiber**

而且它是external modulation。

也就是说laser本身保持比较稳定：

```text
Laser：────────────
              ↓
EAM：   101101001101
```

由EAM负责高速调制。

这样通常：

- chirp比较低
- 高速信号质量好
- dispersion表现好

所以特别适合：

**500m / 2km / 10km级**

这类高速单模链路。

Lumentum也将其InP EML定位于AI/cloud数据中心的short- and medium-reach optical links。citeturn353753search5


你有很多：

- discrete lasers
- coupling
- optical alignment
- MUX
- packaging

而SiPh可以变成：

```text
           ┌──────── SiPh PIC ────────┐
CW Laser → │ Mod1 ─┐                  │
           │ Mod2 ─┼→ MUX → Coupler  │ → Fiber
           │ Mod3 ─┤                  │
           │ Mod4 ─┘                  │
           └───────────────────────────┘
```

很多光学功能：

\[
Modulator + Waveguide + MUX
\]

直接在一块PIC里面完成。

所以SiPh真正的竞争力是：

\[
\boxed{Integration}
\]

而不是：

> “硅光的laser比EML的laser先进。”

这是两种完全不同的逻辑。

# 所以三者真正的技术哲学非常不一样

我给你压缩成三句话：

### VCSEL

> **我把laser做得特别简单、便宜、小，然后直接调它。**

适合：

\[
\boxed{Short\ Reach + Low\ Cost}
\]

### EML

> **我用一个性能很好的InP laser，再集成一个高速EAM调制器。**

适合：

\[
\boxed{High\ Speed + Signal\ Quality + Reach}
\]

### SiPh

> **我不执着于把laser做好，我把modulator、waveguide、MUX等大量光学功能集成到硅PIC上。**

追求：

\[
\boxed{Integration + Scalability}
\]

所以更准确地画它们的关系应该是：

```text
                    Optical Transmitter
                           │
            ┌──────────────┴──────────────┐
            │                             │
      Laser-based device             Photonic platform
            │                             │
      ┌─────┴─────┐                      SiPh
      │           │                       │
     EML        VCSEL               CW Laser required
      │           │                       │
Laser + EAM   Direct modulation      Modulator
                                     Waveguide
                                     MUX
                                     Coupler
```

**这里你应该马上发现一个非常重要的问题：EML和SiPh其实也不是100%互斥。**

因为一边是InP active device，一边是Si photonic integration platform，未来甚至可以通过heterogeneous integration把III-V材料和SiPh结合起来。

因此如果你后面要真正比较技术路线，我不建议简单做：

> EML vs SiPh vs VCSEL 谁赢？

而应该拆成两个问题：

\[
\boxed{\text{Laser / Modulation怎么做？}}
\]

以及：

\[
\boxed{\text{光路怎么集成？}}
\]

这样才不会把不同层面的技术重新混到一起。

850 nm 和 1310 nm 指的是**光的波长（wavelength）**。

光通信里，激光不是“随便一种光”，而是在特定波长附近工作。单位 nm 是纳米：

\[
1\,nm=10^{-9}m
\]

所以：

- **850 nm** = 850 纳米
- **1310 nm** = 1310 纳米

它们都属于红外光，人眼基本看不到。

你可以把波长理解成“光信号使用的载波频段”。不同波长在光纤里的传播特性不一样，所以会对应不同的光纤和应用。

| 波长 | 常见光源 | 常配光纤 | 典型特点 |
|---|---|---|---|
| **850 nm** | VCSEL | 多模光纤 MMF | 成本低、适合短距离 |
| **1310 nm** | EML / DFB / SiPh + CW laser | 单模光纤 SMF | 损耗低、色散特性好、适合更远距离 |
| **1550 nm** | DFB/EML/coherent laser等 | 单模光纤 | 光纤损耗更低，长距离通信常见 |

为什么 VCSEL 经常是 850 nm？因为传统数据中心短距 VCSEL + 多模光纤体系非常成熟，器件便宜、容易阵列化，适合机房内部几十米到百米级连接。

为什么 EML / SiPh 经常看到 1310 nm？因为 1310 nm 在单模光纤里很适合数据中心中短距高速传输，尤其是 500 m、2 km 这类链路。

还有一点很重要：**1310 nm 不是只有一个精确波长。**比如 CWDM4 会用大约 1271、1291、1311、1331 nm 四个不同波长，每个波长传一部分数据，再通过 MUX 合到一根光纤里。

所以你后面看到“1310 nm EML”，本质是在说：

> 这颗激光器发出的光，其中心波长大约在 1310 nm 附近。

而不是在说它的传输速率。

**波长和速率是两个完全不同的参数**：850/1310 nm 说的是“光在哪个频段”，100G/200G/lane 说的是“这束光每秒承载多少数据”。

## 一、VCSEL：为什么它存在？

VCSEL解决的是一个非常具体的问题：

> **如果我只需要传几十米/百米左右，为什么要用昂贵、复杂的单模方案？**

VCSEL最大的杀手锏其实不是绝对性能，而是：

\[
\boxed{低成本+低功耗+易阵列化}
\]

它可以直接调制：

```text
Electrical Data
       ↓
     VCSEL
       ↓
      MMF
```

不用：

```text
Laser → 单独modulator → waveguide → ...
```

因此器件结构简单。

另外VCSEL是垂直出光，所以在wafer上特别容易测试，并且很容易做：

```text
● ● ● ● ● ● ● ●
```

这样的阵列。

这对：

\[
8\times200G=1.6T
\]

这种parallel optics非常合适。

Coherent已经展示了基于200G VCSEL的1.6T-SR8模块，而Broadcom也明确把200G VCSEL定位在低功耗、短距AI集群连接。citeturn816737search3turn816737search12

### 那VCSEL技术难在哪里？

它最大的技术难题不是“能不能做laser”，而是：

> **怎么把VCSEL的调制带宽继续往上推。**

传统VCSEL本来特别适合较低lane rate。

但是：

\[
100G/lane
\rightarrow200G/lane
\]

以后，需要更高：

- modulation bandwidth
- slope efficiency
- thermal stability
- linearity

同时又不能：

- 功耗暴涨
- eye closure严重
- BER恶化

因此VCSEL的高速化其实越来越难。

它还有一个天然问题：

### MMF限制

VCSEL一般配multimode fiber。

MMF里面不同mode传播速度不完全一样，会有：

\[
Modal\ Dispersion
\]

因此随着：

**速率 ↑ + 距离 ↑**

信号越来越难保持。

所以VCSEL的强项非常明确：

\[
\boxed{Short\ Reach}
\]

Coherent也明确把其200G/lane VCSEL方案定位于数据中心的short-reach multimode连接。citeturn816737search17

# 二、EML：为什么需要它？

假设现在你说：

> 我要把距离从50m提高到500m、2km，同时还要200G/lane。

VCSEL开始变得困难。

这时候EML的优势就出来了。

EML：

\[
DFB\ Laser + EAM
\]

laser负责稳定地产生continuous-wave光：

```text
────────────
```

EAM负责把数据调上去：

```text
→ EAM → PAM4
```

为什么这样更好？

因为你不是强迫laser本身高速开开关关。

而是：

> **让laser专心发一束质量好的光，让modulator专门负责高速数据。**

这就是external modulation最核心的思想。

Lumentum明确将EML描述为DFB laser与EAM单片集成，并强调其low chirp、高信号保真度以及对100G/200G光互联的适应性。citeturn816737search1turn816737search14

## EML最重要的优势：信号质量

高速率的时候，你特别怕：

### Chirp

也就是调制过程中：

\[
光强变化
\]

同时造成：

\[
光频率/波长变化
\]

光进入fiber之后，色散会把这些频率成分“拉开”，信号就恶化。

EML的EAM external modulation可以很好地控制chirp。

因此：

\[
\boxed{高速 + 中距离}
\]

是EML的传统强项。

Lumentum目前200G EML就是为8×200G的1.6T pluggable设计，强调高带宽、高extinction ratio和热稳定性能。citeturn816737search0

# 三、SiPh：为什么又要搞硅光？

这里最容易误解。

SiPh首先不是为了说：

> “我的laser比EML更牛。”

它主要是在解决另外一个问题：

> **当一个光模块里面需要越来越多modulator、waveguide、MUX、coupler、PD时，我还能不能继续一个个离散器件装？**

因此SiPh的核心价值是：

\[
\boxed{Integration}
\]

例如传统思路可能是：

```text
Laser1 ─ Mod1 ┐
Laser2 ─ Mod2 ├─ MUX → Fiber
Laser3 ─ Mod3 ┤
Laser4 ─ Mod4 ┘
```

SiPh则可以：

```text
         ┌──────────── Silicon PIC ────────────┐
CW Laser → splitter → modulator ─┐
                    → modulator ─┼→ MUX → Fiber
                    → modulator ─┤
                    → modulator ─┘
         └─────────────────────────────────────┘
```

大量：

- waveguide
- modulator
- splitter
- MUX
- coupler
- photodiode

可以做到PIC上。

这就是硅光存在的根本理由。

Coherent目前的1.6T DR8 SiPh模块已经实现200G electrical + optical interfaces。citeturn816737search2

# SiPh真正难在哪里？

很多人会觉得：

> “硅工艺这么成熟，那SiPh应该最容易。”

实际上未必。

它的问题主要集中在三个地方。

### ① Silicon不好发光

Si是indirect bandgap。

所以：

\[
SiPh\ PIC
\]

通常还需要：

\[
InP/GaAs\ laser
\]

这意味着你还是需要解决：

**III-V → Silicon**

之间的laser integration / coupling。

所以SiPh没有把laser问题消灭。

它只是把：

> laser和光路分工了。

---

### ② Coupling非常难

光在一个几百nm级的waveguide里跑。

最后要进去fiber。

因此需要：

- grating coupler
- edge coupler
- fiber attach

稍微alignment不好：

\[
Insertion\ Loss↑
\]

你的link budget直接被吃掉。

所以SiPh非常强的地方也是它的难点：

> **所有东西集成在很小的空间里以后，对coupling和packaging精度要求非常高。**

---

### ③ Thermal

Si modulator的性能对温度可能比较敏感。

尤其micro-ring类型结构，resonance wavelength会随temperature变化。

于是可能需要：

- heater
- thermal control
- tuning

这又会反过来增加power。

所以SiPh不是：

\[
Integration\Rightarrow一定低功耗
\]

而是需要看具体architecture。

| 路线 | 100G/lane | 200G/lane | 400G/lane | 最先暴露的瓶颈 | 原有优势能否保持 |
|---|---|---|---|---|---|
| **VCSEL** | 很舒服 | 能做，但明显变难 | 挑战很大 | **调制带宽 + MMF色散/距离** | 短距低成本优势仍强 |
| **EML** | 成熟 | 很强 | 已有D-EML原型 | **器件带宽 + driver + 热** | 高信号质量/中距优势较强 |
| **SiPh** | 成熟 | 很强 | 有明确演进路径 | **laser + coupling + packaging + thermal** | **集成优势反而增强** |

下面把原因拆开。

---

# 一、100G/lane：三个路线其实都比较舒服

这一代可以大致理解为：

\[
8\times100G=800G
\]

三种技术都有自己的甜蜜区。

### VCSEL

典型：

\[
850nm + MMF
\]

特点：

**便宜、低功耗、简单、短距离**

所以数据中心里面如果：

> 30m、50m、100m左右就够了

VCSEL非常有竞争力。

Coherent也明确表示，oxide-aperture VCSEL已经被用于100G/lane，包括8×100G的800G multimode模块。citeturn815798search34

---

### EML

典型：

\[
1310nm + SMF
\]

优势：

**信号质量很好 + 500m/2km能力强**

所以scale-out、机房之间、交换机之间需要更远距离时，EML很合适。

Lumentum目前仍把100G/200G EML定位于AI和云数据中心的short/medium reach互联。citeturn815798search7

---

### SiPh

100G/lane也已经非常成熟。

优势不是：

> “我的signal一定比EML更好。”

而是：

> **我可以把modulator、waveguide、MUX、PD等集成起来。**

所以100G时代三者其实都没有被逼到极限。

---

# 二、100G → 200G/lane：第一次明显分化

这对应：

\[
8\times200G=1.6T
\]

现在我们开始看到三个路线的不同问题。

---

# 1. VCSEL：第一个碰到的是“器件带宽”

这是三条路线里面最容易理解的。

传统oxide-aperture VCSEL大约在：

\[
27GHz
\]

附近开始碰到调制带宽限制。

Coherent自己明确说，100G/lane使用的传统oxide-aperture VCSEL已经接近约27GHz bandwidth limit，因此200G/lane需要新的VCSEL结构。citeturn815798search34

也就是说：

\[
100G/lane
\]

还能比较舒服。

到了：

\[
200G/lane
\]

你必须重新设计VCSEL。

所以Coherent后来做了：

**lithographic-aperture VCSEL**

等新结构。

---

## 但200G VCSEL已经做出来了

这点必须强调。

不能说：

> “VCSEL到200G就死了。”

Coherent在2025年已经展示：

\[
8\times200G=1.6T\ SR8
\]

的VCSEL模块。citeturn815798search18

Broadcom也已经推出200G/lane DSP + VCSEL driver，明确针对AI cluster里的低功耗短距MMF连接。citeturn815798search30

所以：

> **200G/lane不是VCSEL的终点，但它已经开始需要明显的器件创新。**

---

# VCSEL第二个问题更麻烦：距离

即使VCSEL本身继续变快，

它通常还是：

\[
850nm+MMF
\]

而MMF的问题不会因为laser变快就消失。

随着：

\[
Baud\ Rate↑
\]

modal dispersion越来越严重。

所以：

\[
Speed↑
\times
Distance↑
\]

对VCSEL特别不友好。

这意味着一个非常重要的事情：

> **VCSEL最大的短板不是“做不到高速度”，而是“高速度以后还能传多远”。**

因此它很可能继续守住：

### Scale-up / rack-scale

例如：

- GPU ↔ switch
- rack内部
- 相邻rack
- 很短距离

而不会因为200G VCSEL出现，就去全面打500m/2km的EML/SiPh市场。

---

# VCSEL真正能保持的优势

即使到了200G：

\[
\boxed{Cost + Power + Simplicity}
\]

还是很强。

所以如果未来AI scale-up大量需要：

\[
10m-50m
\]

这样的连接，

VCSEL甚至可能比很多人预期活得更好。

Broadcom 2026年还公开提出VCSEL-based NPO，目标就是把VCSEL继续用于下一代AI scale-up互联，甚至概念上延伸到3.2T engine。citeturn815798search29

这点非常重要：

> **不要因为SiPh/CPO很热门，就默认VCSEL一定被淘汰。**

---

# 三、EML：200G/lane实际上是它的强势区间

EML到了：

\[
200G/lane
\]

目前仍然相当有竞争力。

例如Lumentum的200G EML支持：

\[
115GBd\ PAM4
\]

并覆盖DR/FR最高约2km的链路。citeturn815798search27

因此：

\[
8\times200G=1.6T
\]

完全成立。

---

# 为什么EML在200G还能保持优势？

因为它的原始设计哲学就是：

> laser负责发好光，
> EAM负责高速调制。

所以在：

**高速 + 500m/2km**

这样的场景里，它还是很舒服。

特别是如果数据中心需要：

- 单模
- 高OMA
- low chirp
- 好TDECQ
- 较大link margin

EML的传统优势还存在。

因此我不会认为：

> 1.6T时代SiPh一定马上把EML吃掉。

实际上Marvell、Broadcom、Lumentum、Coherent到现在都还在推进200G EML路线。citeturn815798search7turn815798search30

---

# 但是EML在200G开始出现一个越来越严重的问题：

## Heat density

Lumentum自己提到：

> 200G/lane以后，InP芯片上的heat density明显增加。

温度变化会影响：

- wavelength
- extinction ratio
- reliability

所以thermal control越来越重要。citeturn815798search9

这已经给400G/lane埋下伏笔。

---

# 四、EML真正的压力在200G → 400G/lane

假设未来：

\[
8\times400G=3.2T
\]

你需要400G optical lane。

这时候传统single-ended EML开始非常困难。

问题来自几个地方：

### ① EAM bandwidth

调制器必须越来越快。

### ② Driver bandwidth

不是只有EML要快：

\[
Driver\rightarrow EML
\]

整个RF path都必须支持极高baud rate。

### ③ Electrical parasitics

包括：

- capacitance
- inductance
- package
- bond wires
- RF trace

在100G时代不严重的问题，到400G都会被放大。

### ④ Thermal

lane power密度继续增加。

---

# 所以现在出现了一个非常重要的东西：

\[
\boxed{Differential\ EML}
\]

Lumentum在2026年已经展示：

\[
4\times400G\ D\text{-}EML
=
1.6T\ DR4
\]

而且明确把它作为未来3.2T模块的stepping stone。citeturn815798search13

这个案例特别重要。

它说明：

> **EML不是到400G/lane就没路，而是需要改变架构。**

所以EML的演进实际上是：

\[
Single-ended\ EML
\]

↓

\[
Differential\ EML
\]

↓

继续挑战400G/lane。

---

# 五、SiPh的情况完全不一样

SiPh从100G→200G→400G，真正发生的是：

> **它原来最大的优势——integration——变得越来越值钱。**

为什么？

100G时代：

一个模块可能只有：

\[
4/8\ optical\ channels
\]

做几个离散器件其实还能接受。

但如果未来系统需要：

- 更多lane
- 更多laser
- 更多modulator
- 更多MUX
- 更复杂optical routing
- CPO

离散光学会越来越复杂。

这时候SiPh可以把：

\[
Modulator
+
Waveguide
+
MUX
+
Splitter
+
PD
\]

做到一个PIC。

所以：

\[
\boxed{Channel\ Count↑
\Rightarrow SiPh\ Integration\ Value↑}
\]

---

# 这是为什么SiPh越往3.2T越值得关注

Marvell现在的1.6T silicon-photonics light engine已经把：

- SiPh
- linear driver
- TIA
- controller

做到一个高度集成的engine里，并支持：

\[
200G/lane
\]

用于1.6T LPO。citeturn815798search3

而Broadcom的CPO现在也已经做到200G/lane，并明确在开发400G/lane的下一代CPO。citeturn815798search2turn815798search22

所以从技术演进看：

\[
100G
\rightarrow
200G
\rightarrow
400G/lane
\]

SiPh的**战略地位反而越来越强**。

---

# 但是SiPh不是没有瓶颈

而且它的瓶颈和EML/VCSEL完全不同。

## SiPh第一个问题：laser

Silicon自己不好发光。

所以你还是需要：

\[
CW\ Laser
\]

通常来自III-V材料。

因此：

\[
SiPh
\neq
把InP/GaAs消灭
\]

反而可能变成：

\[
\boxed{
III\!-\!V\ Laser
+
SiPh\ PIC
}
\]

---

# 第二个问题：Coupling

这个我认为你做产业研究时应该特别注意。

你把越来越多光路集成到PIC以后：

\[
Laser
\rightarrow
SiPh
\]

以及：

\[
SiPh
\rightarrow
Fiber
\]

都必须极精准。

否则：

\[
Coupling\ Loss↑
\]

直接吃掉link budget。

所以SiPh越集成：

> **光学封装反而越重要。**

这就是为什么未来：

- FAU
- edge coupler
- fiber attach
- precision packaging

可能获得越来越高价值量。

---

# 第三个问题：热

特别是某些：

**ring modulator**

对温度非常敏感。

温度一变：

\[
resonance\ wavelength
\]

就会漂移。

于是要：

- heater
- monitor
- thermal tuning
- control loop

这又可能增加power。

所以：

> **SiPh = 一定低功耗**

这个说法是不严谨的。

真正的优势是：

\[
\boxed{Integration}
\]

低功耗要看具体architecture。

# 六、因此100→200→400G真正的技术分化是这样

我给你画成一条时间轴：

```text
               100G/lane
                   │
        ┌──────────┼──────────┐
        │          │          │
      VCSEL       EML        SiPh
      很舒服      很舒服      很舒服
        │          │          │
        ▼          ▼          ▼

        │          │          │

        │          │          │

        │          │          │
```

# 七、如果只看数据中心，我目前会这么判断

## 100G/lane时代

**三者共存。**

没有必要判断赢家。

---

## 200G/lane / 1.6T时代

我认为会形成非常明显的三分：

### 超短距 / scale-up

\[
\boxed{VCSEL仍然很有竞争力}
\]

原因：

**低功耗 + 低成本。**

200G VCSEL已经被Coherent/Broadcom等推进到AI集群连接。citeturn815798search18turn815798search30

---

### 500m / 2km scale-out

\[
\boxed{EML\ vs\ SiPh}
\]

这才是比较激烈的地方。

EML：

**signal quality / mature manufacturing**

SiPh：

**integration / scaling**

---

### CPO / 超高密度

\[
\boxed{SiPh明显占优势}
\]

Broadcom当前CPO就是很典型的silicon photonics方向，并已经公开200G/lane CPO和400G/lane下一代开发路径。citeturn815798search10turn815798search22

# 八、到了400G/lane，我的判断会发生明显变化

如果目标是：

\[
3.2T
\]

我会重点观察三件事情：

### VCSEL

**最大问题：**

\[
\boxed{Bandwidth\times Reach}
\]

能不能在继续保持低功耗低成本的情况下，把200G推进400G？

**风险最高。**

但如果scale-up选择更多parallel lanes，而不是硬推400G/lane，VCSEL可以绕开这个问题。

---

### EML

**最大问题：**

\[
\boxed{Bandwidth + RF\ drive + Thermal}
\]

但目前D-EML已经证明400G/lane并非完全不可行。Lumentum 2026年的1.6T DR4就是重要验证。citeturn815798search13

所以我会把EML判断为：

> **技术难度大幅增加，但仍有明确演进路线。**

---

### SiPh

它的问题不是首先“能不能集成更多通道”。

这个恰恰是它的强项。

它会越来越被：

\[
\boxed{
Laser\ efficiency
+
Coupling
+
Packaging
+
Thermal
+
Yield
}
\]

约束。

所以SiPh最大的风险是：

> **器件能做出来，但整个光引擎是不是能低成本、高良率、大规模制造？**

这是一个非常不同的瓶颈。

---

# 最后给你一个我认为最重要的结论

如果只看AI数据中心，我不会预测：

\[
VCSEL\rightarrow EML\rightarrow SiPh
\]

这种简单替代。

我更倾向于：

\[
\boxed{
Reach\ Segmentation
+
Integration\ Segmentation
}
\]

形成：

**超短距：VCSEL**

→ 只要能满足距离，成本/功耗优势很难被轻易打掉。

**中短距pluggable：EML vs SiPh**

→ 这是未来1.6T/3.2T最值得观察的竞争。

**高密度/CPO：SiPh**

→ lane rate和总bandwidth越高，SiPh集成价值越明显。

所以从投资研究角度，我现在最想继续往下挖的反而不是“谁最终胜出”，而是这三个**瓶颈发生迁移**：

\[
\boxed{
VCSEL:\ Device\ Bandwidth
}
\]

\[
\boxed{
EML:\ RF/thermal
}
\]

\[
\boxed{
SiPh:\ Packaging/coupling/laser
}
\]

**谁的瓶颈对应的供应链环节最难扩产、价值量提升最快，那里才可能是800G→1.6T→3.2T真正的机会。**

对，你这个纠正是对的。**我前面把“SiPh 可以减少 modulator 数量”说得不准确。**

如果传输仍然需要 **N 条独立高速光通道**，通常还是需要 **N 个调制器功能**。硅光真正减少的，主要不是“调制器数量”，而是：

> **把很多原本分立的 modulator、waveguide、MUX、splitter、PD 等做进同一块 PIC，同时允许一颗高功率 CW laser 给多个通道供光。**

Broadcom也明确提到，一颗独立CW laser可以支持多个数据通道，从而降低功耗和成本。citeturn606049search8

例如 8×200G 的1.6T，逻辑上仍然是：

\[
8\ \text{data lanes} \Rightarrow 8\ \text{modulation functions}
\]

### EML 路线

每个lane往往对应一个“发光+调制”的器件：

```text
Lane 1: DFB + EAM
Lane 2: DFB + EAM
Lane 3: DFB + EAM
...
Lane 8: DFB + EAM
```

粗略可以理解成：

\[
8\ lasers + 8\ modulators
\]

因为每颗EML内部本身就是 **DFB laser + EAM**。

### SiPh路线

可以变成：

```text
             ┌─ Modulator 1
             ├─ Modulator 2
CW Laser ────┼─ Modulator 3
   /lasers   │   ...
             └─ Modulator 8
                   ↓
              MUX / waveguide
                   ↓
                 Fiber
```

仍然有：

\[
8\ modulators
\]

但可能不再需要：

\[
8\ independent\ lasers
\]

而是：

\[
1\text{或少数几个高功率 CW lasers}
\rightarrow
多个SiPh modulation channels
\]

Coherent也把这一组合直接描述为 **CW InP laser + silicon photonics modulators**；其高功率CW laser就是为800G/1.6T SiPh transceiver的多个调制通道供光。citeturn606049search6turn606049search15

---

所以SiPh真正的“器件数量减少”要说得更精确。

它减少/合并的是：

**① Laser数量可能减少**

这是你指出的最重要的一点。

EML：

\[
Laser_1+Mod_1
\]
\[
Laser_2+Mod_2
\]
\[
...
\]

SiPh：

\[
CW\ Laser
\rightarrow
Mod_1,Mod_2,...Mod_N
\]

---

**② 独立光学元件数量明显减少**

例如原来可能需要分立的：

- splitter
- MUX
- DEMUX
- waveguide/interconnect
- coupler相关结构
- photodiode

SiPh可以把其中大量功能直接做到PIC里。

Coherent的一款SiPh 2×400G产品就明确强调，PIC集成可以降低component count、简化生产。citeturn606049search12

---

**③ 但 modulator 本身不能因为“集成”凭空消失**

这是最关键的修正。

如果：

\[
8\times200G
\]

是8条独立光lane，那么一般仍需要：

\[
8\times modulation
\]

区别只是：

**EML：**

> 8个调制器分散在8颗InP EML器件里。

**SiPh：**

> 8个调制器可以全部做在同一块SiPh PIC上。

所以应该区分：

\[
\boxed{\text{Modulator count}}
\]

和

\[
\boxed{\text{Discrete component count}}
\]

SiPh主要降低的是**后者**。

---

这其实进一步修正了我们前面说的“SiPh随着通道数增加优势越来越大”的理由。

不能说：

> ❌ 通道越多 → SiPh需要的modulator越少。

而应该说：

> ✅ 通道越多 → 所需modulator数量仍然增加，但把这些modulator以及MUX、waveguide等集成在一块PIC上的价值越来越大。

例如从4 lane变8 lane：

### 离散EML体系

\[
4\ EML \rightarrow 8\ EML
\]

laser数量、active devices、placement/alignment基本一起增长。

而SiPh：

\[
4\ modulators\ on\ PIC
\rightarrow
8\ modulators\ on\ PIC
\]

PIC面积会增加、设计会复杂，但不一定意味着封装对象数量也翻倍。

这才是：

\[
\boxed{Integration\ scaling}
\]

真正的含义。

因此如果我们重新比较 EML vs SiPh，最准确的区别其实是：

| | EML | SiPh |
|---|---|---|
| 8 optical lanes | 8个EAM modulation functions | 8个Si modulation functions |
| Laser | 通常每个EML自带laser | **一颗/少数CW laser可供多个channel** |
| Modulator | 8个 | **还是8个** |
| Modulator位置 | 分散在不同EML die | **集成在一块PIC** |
| MUX/waveguide | 更多分立/混合集成 | **PIC内集成** |
| 通道增加时 | active device/assembly随之增加 | **PIC规模扩大，但分立件增长较慢** |

所以你这个点非常重要：**SiPh的价值主要是“共享laser + 光路集成”，而不是“减少数据通道所需要的modulator”。**

而这会进一步带出一个很关键的问题：如果未来从 **8×200G 变成 4×400G**，那才是真的能把 modulator 数量从8个降到4个——但这是**lane rate提高带来的效果，不是SiPh本身带来的效果**。

可以。先聚焦**数据中心里的 pluggable optics**，把这四个东西放在同一张图上看，最容易理解。

核心区别其实就一句话：

> **DSP / TRO / LRO / LPO 的本质，是“光模块内部到底保留多少数字重定时和均衡能力”。**

可以把它理解成一个连续谱：

\[
\boxed{\text{Full DSP} \rightarrow \text{TRO/LRO} \rightarrow \text{LPO}}
\]

越往右：

- DSP功能越少
- 功耗越低
- latency越低
- 但对host SerDes、channel quality、系统调试的要求越高

OIF 的资料也把 full-retimed module 和 linear optics 明确区分开：传统 retimed module 内部有 DSP，而 LPO 的目标就是取消模块内的 retiming DSP。citeturn272525search0turn272525search7

# 1. 先从传统 DSP 光模块开始

传统结构大概是：

```text
Switch ASIC
    │
Host SerDes
    │
    ▼
┌──────── Optical Module ────────┐
│                                │
│     Optical DSP                │
│   ┌──────────────┐             │
│ → │ CDR / EQ     │             │
│   │ Retiming     │             │
│   │ Gearbox      │             │
│   │ Signal Proc. │             │
│   └──────┬───────┘             │
│          ↓                     │
│       Driver → Laser/Modulator │
│                                │
│ PD → TIA → DSP                 │
└────────────────────────────────┘
```

DSP最重要的作用不是“把电变成光”。

真正电→光的是：

- driver
- laser/modulator

DSP主要是在前面做：

\[
\boxed{\text{把一个已经变差的高速电信号重新整理干净}}
\]

包括：

- equalization
- CDR，clock/data recovery
- retiming
- gearbox
- PAM4 DSP
- signal conditioning

Marvell目前仍把PAM4 optical DSP定位为数据中心内部400G/800G/1.6T pluggable的核心方案，特别强调其对信号完整性和距离的支持。citeturn272525search6turn272525search25

---

# 为什么要有DSP？

假设Switch ASIC发出来：

```text
完美 PAM4
│ │ │ │
```

经过：

- package
- PCB
- connector
- module electrical interface

以后，到了光模块：

```text
╲╱╲___╱╲__
```

已经失真了。

DSP可以重新：

\[
Equalize \rightarrow Recover\ Clock \rightarrow Retiming
\]

变成比较干净的signal，再送给driver。

所以DSP的最大优势其实是：

\[
\boxed{Margin}
\]

它让模块比较“傻瓜”。

只要接口符合标准：

> 插进去，大概率就能跑。

这就是为什么传统DSP模块interop很好、部署比较简单。

---

# 但DSP最大的问题是什么？

## 功耗

到了：

\[
100G/lane \rightarrow 200G/lane
\]

DSP的高速ADC/DAC、SerDes、equalizer、CDR等都越来越耗电。

于是模块里：

> 光学器件未必是最大耗电者，DSP本身可能已经占很大一块。

这就出现了一个问题：

\[
1.6T
\]

如果继续全部DSP：

\[
Power↑
\]

于是大家开始想：

> **是不是可以把DSP里面一些功能删掉？**

这就是TRO/LRO/LPO出现的根源。

---

# 2. LPO：最激进

先讲最容易理解的LPO。

LPO：

**Linear Pluggable Optics**

基本思路：

```text
Switch ASIC
     │
 powerful SerDes
     │
     ▼
┌────── LPO module ──────┐
│                        │
│ Linear Driver          │
│      ↓                 │
│ Modulator / Laser      │
│                        │
│ PD → Linear TIA        │
└────────────────────────┘
```

模块里面：

\[
\boxed{\text{没有传统的retiming DSP}}
\]

OIF当前的linear interface工作就是面向LPO、NPO和CPO，希望支持224G级full-linear electrical interfaces。citeturn272525search15turn272525search32

Marvell目前的1.6T LPO chipset甚至直接就是：

- 200G/lane TIA
- laser driver

而不是传统完整optical DSP。citeturn272525search18

---

## 为什么叫Linear？

因为它尽量不重新“数字化—恢复—再生成”。

大概变成：

\[
Electrical\ PAM4
\]

直接经过：

\[
Linear\ Amplification
\]

送给modulator。

接收端类似：

\[
PD\rightarrow TIA
\]

然后把模拟PAM4交回host ASIC处理。

所以：

> **host ASIC的SerDes承担了以前module DSP的一部分工作。**

---

# LPO最大的优势：功耗

你直接把一个高功耗DSP拿掉。

所以：

\[
\boxed{W/Tbps↓}
\]

这是LPO最大的卖点。

另外：

\[
Latency↓
\]

因为没有中间：

\[
CDR \rightarrow DSP \rightarrow Retiming
\]

OIF和IEEE资料都把降低power和latency列为LPO的重要优势。citeturn272525search3turn272525search15

---

# 但LPO的代价非常明显

这个一定要理解。

传统DSP模块：

```text
Bad-ish signal
     ↓
   DSP
     ↓
Clean signal
```

LPO：

```text
Bad-ish signal
     ↓
直接放大
     ↓
还是 bad-ish signal
```

所以整个链路：

\[
ASIC\ SerDes
\rightarrow PCB
\rightarrow Connector
\rightarrow Module
\rightarrow Optical
\]

必须作为**一个整体系统**优化。

这就导致：

### Host SerDes要求更高

ASIC要有：

- 更强TX equalization
- 更强RX equalization
- 更好CDR
- 更好的signal margin

### PCB要求更高

loss/crosstalk控制更严格。

### Module interchangeability下降

以前：

> 模块A换模块B，大概率可以。

LPO时代：

> ASIC + board + module必须一起调。

所以LPO是：

\[
\boxed{
Power↓,\ Latency↓
}
\]

交换：

\[
\boxed{
System\ Complexity↑,\ Margin↓
}
\]

---

# 3. TRO：不要一次把DSP全删掉

TRO：

**Transmit Retimed Optics**

这个概念其实很好理解：

> **发送端保留retiming，接收端linear。**

粗略结构：

```text
TX:

ASIC
 ↓
Retimer / DSP
 ↓
Driver
 ↓
Optics


RX:

Optics
 ↓
TIA
 ↓
Linear signal
 ↓
ASIC
```

OIF 2026年的Compute Optics Interface材料将TRO描述为一种“half-retimed” architecture。citeturn272525search7

为什么这么设计？

因为TX方向往往比较担心：

\[
Host\ electrical\ signal
\rightarrow
optical\ transmitter
\]

如果信号质量不好，会直接污染optical Tx。

所以保留TX retiming：

\[
\boxed{保证optical transmitter质量}
\]

但RX不再做完整DSP：

\[
\boxed{省掉一部分power}
\]

所以TRO其实就是一个折中：

\[
Full\ DSP
\]

和

\[
LPO
\]

之间。

---

# 4. LRO：反过来

LRO通常指：

**Linear Receive Optics**

核心就是：

> 一边linear，一边保留更多retimed处理。

不同产业材料有时对具体implementation叫法并不完全统一，所以不要把缩写理解成绝对唯一的电路定义；IEEE讨论里也把linear、retimed以及“half-linear / LRO”作为不同PHY实现选项来讨论。citeturn272525search20

你可以先抓住本质：

\[
\boxed{\text{只去掉一个方向的完整DSP}}
\]

而不是像LPO：

\[
\boxed{\text{两个方向都尽可能linear}}
\]

---

# 这样你就能理解为什么有这么多路线了

如果只有两个目标：

- 功耗
- 信号质量

那就是一个trade-off：

```text
Signal margin / interoperability
↑
│     Full DSP
│
│          TRO / LRO
│
│                    LPO
│
└────────────────────────→ Power saving
```

不是说：

> LPO比DSP先进。

而是：

### Full DSP

追求：

\[
\boxed{Robustness}
\]

优势：

- 最大link margin
- interoperability最好
- host要求低
- 长距离能力更容易保证
- deployment成熟

代价：

- power高
- latency高一点
- DSP成本

---

### TRO / LRO

追求：

\[
\boxed{Compromise}
\]

优势：

- 比full DSP省电
- 比LPO有更好的margin
- 可以逐步迁移

代价：

- 架构复杂
- 节省的功耗没有LPO那么多

---

### LPO

追求：

\[
\boxed{Power/Latency}
\]

优势：

- 最低DSP power
- latency低
- module BOM可能下降

代价：

- channel margin更紧
- host SerDes必须非常强
- interoperability难
- 系统协同设计要求高

---

# 对AI数据中心而言，为什么现在特别讨论LPO？

因为AI把两个东西同时推高：

\[
Bandwidth↑
\]

和：

\[
Optical\ Link\ Count↑
\]

于是DSP功耗开始被放大。

假设一个800G/1.6T模块里DSP多消耗几瓦：

单模块没什么。

但如果：

\[
100,000+
\]

个光连接，

就是：

\[
MW\ level
\]

的系统问题。

所以现在不是大家突然发现DSP“不好”，而是：

> **DSP提供的signal margin仍然非常有价值，但它的power cost越来越贵。**

因此产业才开始尝试：

\[
Full\ DSP
\rightarrow
TRO/LRO
\rightarrow
LPO
\]

逐步把signal processing从module：

\[
\boxed{搬回ASIC}
\]

Marvell现在甚至同时保留完整DSP产品和1.6T LPO chipset，这恰好说明行业不是“DSP被LPO淘汰”，而是在针对不同link场景做不同trade-off。citeturn272525search12turn272525search18

---

# 最重要的是：这些路线和EML / SiPh / VCSEL是两个维度

这正好回到我们前面拆技术树的原因。

例如：

### SiPh + DSP

完全可以：

```text
ASIC → DSP → Driver → SiPh Modulator
```

### SiPh + LPO

也可以：

```text
ASIC → Linear Driver → SiPh Modulator
```

### VCSEL + DSP

也存在：

```text
ASIC → DSP → VCSEL Driver → VCSEL
```

Marvell已有集成TIA和VCSEL driver的400/800G PAM4 DSP。citeturn272525search29

### VCSEL + LPO

也可以：

```text
ASIC → Linear Driver → VCSEL
```

所以：

> **EML/SiPh/VCSEL回答的是“光怎么产生/调制”；**
>
> **DSP/TRO/LRO/LPO回答的是“高速电信号在哪里被恢复和处理”。**

这是两个正交维度。

---

## 如果你的目标是判断800G→1.6T→3.2T，我会这样看

### 800G / 100G-lane

**Full DSP非常成熟**

LPO更多是降低功耗的alternative。

### 1.6T / 200G-lane

开始变得非常有意思：

\[
DSP\ Power↑
\]

所以：

\[
LPO\ value↑
\]

但是与此同时：

\[
200G\ SerDes\ margin↓
\]

所以LPO的难度也提高。

**这正是LPO现在竞争最激烈的阶段。**

### 3.2T / 400G-lane

这是最大的问题：

如果lane继续变成：

\[
400G
\]

那么没有DSP以后：

> host SerDes + PCB + package + linear optics 能不能把整个链路margin控制住？

可能非常困难。

所以未来不是一定：

\[
DSP\rightarrow LPO
\]

更有可能出现：

\[
\boxed{
Full\ DSP / TRO / LRO / LPO
}
\]

根据reach和system architecture长期共存。

我会把这四条路线的本质最后压缩成一句：

> **它们争的不是“谁能发光”，而是高速链路恶化之后，到底在哪里付出功耗把信号重新修好。**

这句话其实就是整个 Electrical Architecture 层存在的原因。

可以。沿用我们前面分析 **DSP / TRO / LRO / LPO** 的方法论，这次只看**数据中心内部互联**，把 Pluggable / NPO / CPO 当成一个问题来理解：

> **高速电信号从交换 ASIC 出来以后，要走多远，才变成光。**

这三条路线的本质不是“光学原理不同”，而是：

\[
\boxed{\text{Optics 离 ASIC 有多近}}
\]

距离越近，电通道越短，功耗和信号完整性通常越好；但封装、散热、维修、供应链复杂度会明显上升。

---

## 先看最核心的结构

### 1. Pluggable

```text
Switch ASIC
    │
    │  较长高速PCB走线
    │
    ▼
Front Panel
    │
[ Pluggable Optical Module ]
    │
   Fiber
```

光模块插在交换机前面板。

### 2. NPO — Near-Packaged Optics

```text
Switch ASIC
    │
    │ 很短电连接
    ▼
Optical Engine
   （在ASIC附近）
    │
    │ fiber
    ▼
Front Panel Connector
```

光引擎离ASIC很近，但**不是和ASIC在同一个封装基板里**。

### 3. CPO — Co-Packaged Optics

```text
┌──────── Host Package ────────┐
│                              │
│  Switch ASIC  ↔ Optical Engine
│                              │
└──────────────────────────────┘
             │
            Fiber
```

光引擎和交换ASIC进入同一个co-package。

OIF对CPO的定义就是把active optical components放在与ASIC共享的封装/基板体系内；NPO则是位于package附近的独立光引擎。citeturn787101search4turn787101search25

---

# 一、为什么最开始是 Pluggable？

因为它的工程逻辑极其漂亮：

> **交换机负责交换，光模块负责光通信，两边通过标准接口连接。**

坏了怎么办？

拔掉：

```text
[坏800G模块] → 拔掉 → [新800G模块]
```

不用动交换ASIC。

这带来几个巨大的优势：

### ① 可维护性最好

模块坏了，现场直接换。

### ② Vendor interoperability好

理论上符合标准的模块可以来自不同供应商。

### ③ 升级简单

同一台交换机可以根据设计支持不同模块/距离。

### ④ 制造和测试解耦

交换ASIC和光模块：

- 分别生产
- 分别测试
- 最后组装

所以yield风险不会被完全绑在一起。

这其实是Pluggable能够成为数据中心主流形态最根本的原因。

---

# 但Pluggable为什么开始遇到问题？

最核心的问题不是“模块本身不够先进”。

而是：

\[
\boxed{\text{ASIC → Front-panel module 的高速电连接越来越难}}
\]

假设ASIC到模块之间有：

**10 cm / 20 cm甚至更长PCB trace**

在100G/lane时还能处理。

到了：

\[
200G/lane
\]

信号在PCB上传输以后：

- insertion loss ↑
- crosstalk ↑
- jitter ↑
- eye closure ↑

然后就要：

- 更强SerDes
- 更多equalization
- retimer
- DSP

于是：

\[
Power↑
\]

Broadcom对200G/lane的讨论就明确指出，到了这一代，很多板级走线会开始超过可接受的loss budget，这也是推动optics靠近switch silicon的重要原因。citeturn787101search34

---

# 二、NPO为什么出现？

NPO的想法其实很直白：

> **既然问题是ASIC到前面板太远，那我先别激进到CPO，先把光模块搬到ASIC旁边不就行了？**

所以：

```text
Pluggable:

ASIC ─────────────── Optical module
        长PCB


NPO:

ASIC ── Optical Engine
        很短PCB
```

这样立刻解决一个问题：

\[
\boxed{\text{Electrical Reach 大幅缩短}}
\]

OIF的XSR类电接口本来就是面向这种非常短的die-to-optical-engine连接，包括NPO和CPO。citeturn787101search25

---

# NPO最大的优势

## ① 降低SerDes / electrical power

PCB走线短以后：

- 不需要那么强的equalization
- insertion loss降低
- SerDes驱动功耗可以下降

所以：

\[
W/Tbps ↓
\]

---

## ② 保留一部分模块化

这是NPO非常重要的一点。

它不像CPO那么彻底。

Optical Engine仍然可以是：

\[
独立模块
\]

因此理论上：

- 测试容易一些
- 更换容易一些
- yield解耦更好

所以NPO可以理解为：

\[
\boxed{\text{Pluggable 的工程友好性}}
\]

和

\[
\boxed{\text{CPO 的短电连接}}
\]

之间的折中。

---

# NPO的问题在哪里？

### 第一个：维护还是没有Pluggable方便

如果optical engine在交换机内部ASIC旁边：

你就不能：

> 打开前面板 → 拔一个QSFP/OSFP → 换掉

而可能需要：

- 打开设备
- 更换内部optical engine
- 更复杂的service procedure

---

### 第二个：fiber routing复杂

Optics已经在ASIC附近：

```text
ASIC + Optical Engine
       │
       │ optical fiber
       ▼
Front Panel
```

所以机箱内部需要把fiber从芯片附近引到前面板。

这又带来：

- fiber routing
- bend radius
- connector
- assembly

这些新问题。

---

### 第三个：热

ASIC附近是什么地方？

**整台交换机最热的地方之一。**

所以你把laser / modulator / photonics搬过去：

\[
Temperature↑
\]

会影响：

- laser efficiency
- wavelength stability
- modulator
- reliability

因此NPO并不是“把模块挪近一点”这么简单。

---

# 三、CPO为什么还要再进一步？

CPO基本上是在说：

> **既然电连接越短越好，那干脆把Optical Engine放到ASIC封装旁边。**

于是：

```text
Pluggable
ASIC ─────────────── optics


NPO
ASIC ── optics


CPO
[ ASIC | optics ]
```

高速electrical distance进一步缩短。

Broadcom和NVIDIA现在推进CPO的核心卖点就是减少高功耗长距离electrical SerDes连接，从而提升AI网络的power efficiency和signal integrity。citeturn787101search6turn787101search11

---

# CPO最重要的优势是什么？

很多人第一反应是：

> “提高集成度。”

这没错，但**不是最重要的系统原因**。

真正最重要的是：

\[
\boxed{\text{缩短高速 electrical link}}
\]

从：

```text
ASIC package
   ↓
PCB
   ↓
connector
   ↓
pluggable module
```

变成：

```text
ASIC ↔ Optical Engine
```

只走非常短的electrical connection。

---

# 这为什么能省这么多功耗？

因为电信号远距离跑200G/lane特别贵。

你需要很大的：

- Tx swing
- equalization
- FFE
- DFE
- DSP/CDR

如果距离非常短：

\[
Electrical\ Loss↓
\]

于是：

\[
SerDes\ Power↓
\]

也更容易使用：

\[

CPO 功耗降低，对数据中心的价值不只是“省电费”，更重要的是它会同时改善 **算力密度、散热压力和系统可扩展性**。

最直接的好处是 **W/Tbps 下降**。同样搬 1 Tbps 数据，如果 pluggable 光互联需要更多 SerDes / DSP / equalization 功耗，而 CPO 因为高速电距离更短，可以减少这部分能耗，那么整个网络层的功耗就下降。

这会带来几个具体结果。

1. **同一个机架里能放更多算力。**  
数据中心机架有明确的电力上限。网络设备少耗几百瓦、几千瓦，这部分 power budget 就能让给 GPU/加速器。对 AI 数据中心来说，这比单纯省电费更有价值，因为 GPU 才是产生计算价值的设备。

2. **散热压力降低。**  
电功耗最终几乎都会变成热。互联少耗 1 kW，基本就意味着少产生接近 1 kW 的热负荷。这样可以降低风冷/液冷压力，减少冷却系统投入，并让交换芯片、光学器件工作在更容易控制的温度范围。

3. **更容易做到 102.4T、204.8T 甚至更高交换容量。**  
如果每一代交换机带宽翻倍，但网络接口功耗也接近翻倍，最终你会撞上设备和机架的 thermal/power envelope。CPO真正重要的一点是：

\[
\text{Bandwidth} \uparrow
\]

同时努力让：

\[
\text{W/Tbps} \downarrow
\]

否则总带宽很难持续往上堆。

4. **减少高速电 SerDes 的功耗。**  
这是 CPO 相比传统 pluggable 最核心的节能来源之一。传统结构是：

\[
ASIC \rightarrow 长PCB高速电通道 \rightarrow 光模块
\]

为了跑 200G/lane、未来更高，需要更强的 Tx swing、equalization、CDR/retimer 等。

CPO把它变成：

\[
ASIC \leftrightarrow Optical\ Engine
\]

距离很短，于是这段电链路不需要那么“用力”。

所以 CPO 不是单纯让 laser 更省电，而是：

> **减少“把高速电信号从芯片送到远处光模块”这件事情本身的能耗。**

5. **可能降低整个网络的 TCO。**  
电费只是其中一部分，还包括：

- 配电基础设施
- UPS
- cooling
- 风扇/泵
- power delivery
- 机架数量

因此如果 CPO 能稳定降低 W/Tbps，它可能让整个数据中心“每 Tbps 网络能力”的基础设施成本下降。

但这里要注意一个非常重要的 trade-off：

> **CPO省下的是运行功耗，但可能增加封装、散热设计、维修和良率成本。**

所以判断 CPO 有没有经济价值，不能只看：

\[
Power_{CPO}<Power_{Pluggable}
\]

而应该看：

\[
\boxed{

}
\]

包括功耗、冷却、可靠性、维护和制造成本。

如果你从技术路线角度理解，CPO 降功耗最关键的意义其实可以压缩成一句话：

> **它让网络带宽增长得比网络功耗更快，从而避免互联本身成为 AI 算力扩张的电力和散热瓶颈。**

- CDR
- retiming
- signal recovery

发送端：

\[

\]

接收端：

\[

\]

- 更低 crosstalk

\boxed{\text{optical connector / fiber interface 重要性上升}}

4. **不同技术到底解决同一个问题，还是不同问题？**  
   比如：
   - EML vs SiPh：更多是在比较光学实现与集成方式
   - LPO vs DSP：比较信号处理放在哪里
   - CPO vs Pluggable：比较光学离ASIC多远  
   
   先判断是不是同一维度，再比较优劣。

5. **每条路线解决了什么，又引入了什么新问题？**  
   最重要的问法是：
   > A技术解决了哪个瓶颈？代价是什么？新的瓶颈转移到了哪里？

   例如：
   > CPO缩短electrical reach，降低SerDes功耗，但把问题转移到fiber attach、先进封装、散热和可维护性。

6. **随着下一代速率提升，原来的优势还能不能维持？**  
   比如：
   > VCSEL从100G→200G→400G/lane时，低成本优势还能保持吗？最先碰到的是带宽还是距离？
   
   > EML到了400G/lane，信号质量优势还能维持吗？代价是不是driver和thermal急剧变难？
   
   > SiPh随着通道数增加，integration优势是否越来越大？瓶颈会不会转向laser、coupling和yield？

7. **最后才问产业机会。**  
   也就是：
   > 瓶颈从A环节迁移到B环节后，哪个环节价值量提升？哪个环节最难扩产？谁掌握核心能力？

你以后可以直接用这个“万能问题模板”：

> **某项技术升级是由什么系统需求驱动的？当前方案最先遇到什么物理/工程瓶颈？新技术具体解决哪个瓶颈？它付出的代价是什么？瓶颈又被转移到了哪个环节？随着下一代速率继续提升，这个优势是否还能维持？最终哪些供应链环节的价值量会上升？**

拿光模块举例，就是：

> **从800G→1.6T→3.2T，随着lane rate提升，哪些指标最先恶化？EML、SiPh、VCSEL分别解决什么问题；DSP/LPO解决什么问题；Pluggable/NPO/CPO又解决什么问题？每种技术降低了什么成本或功耗，又把难度转移到了哪里？最终谁受益？**

我认为你现在最值得固定下来的方法论就是一句话：

\[
\boxed{
System\ Need
\rightarrow Bottleneck
\rightarrow Technology
\rightarrow Trade\text{-}off
\rightarrow New\ Bottleneck
\rightarrow Supply\ Chain\ Opportunity
}
\]

以后你研究任何硬科技行业，都可以先按这条链问。

```text
Laser chip

      ↓
Optical Interposer
```

\[
\boxed{\text{Photonic Chiplet Platform}}

这是我的类比，不是POET官方产品分类，但很接近它的技术逻辑。POET目前确实强调在一个chip-scale平台上集成来自不同技术体系的电子和光子器件。citeturn552998search4turn552998search5

> **如果我已经能把大量功能在wafer上一次做出来，为什么还要买很多die再拼？**

```text

→ modulator
→ waveguide
→ MUX
→ PD
```

这些东西本来就是同一块PIC。

\boxed{Integration\ Cost}

```text
+
买Driver die

买TIA die
```

Placement

POET要解决的**不是“激光不够快”**，也不是“CPO怎么放”，它解决的是一个更具体的制造/集成问题：

> **高速光模块里的激光器、调制器、PD、TIA、Driver、MUX、waveguide，怎么低成本、高密度、高良率地拼在一起。**

传统做法的问题是，光子器件不像数字芯片那么容易“直接连”。尤其到了800G/1.6T以后，会越来越依赖：

- active alignment
- micro-optics
- wire bonding
- 精密光学组装
- 分立器件测试和封装

这些步骤贵、慢，而且高速以后wire bond还会带来RF寄生、串扰和信号完整性问题。POET自己就把传统wire-bond package和micro-optical alignment列为800G/1.6T继续扩展时的成本、RF串扰、热和良率问题。citeturn945735search3turn945735search6

POET的办法是做一个 **Optical Interposer**：

```text
Laser / EML      Driver
      ↓             ↓
   ┌────────────────────┐
   │ POET Interposer    │
   │ waveguide / MUX    │
   │ optical routing    │
   └────────────────────┘
        ↑          ↑
       PD         TIA
```

核心有三件事。

第一，**把主动对准变成被动对准**。传统laser → waveguide，要边通电/发光边一点点调位置，直到耦合最好，这叫active alignment，很贵。POET希望通过interposer上的结构和flip-chip方式，让laser等器件按预定位置直接放置，实现passive alignment。它明确宣称这种方式可以取消laser-to-waveguide的active alignment并减少昂贵的对准设备。citeturn945735search1turn945735search7

第二，**减少高速wire bond**。200G/lane以后，一根wire bond已经不是简单导线，而会产生inductance、RF loss、crosstalk。POET在1.6T engine里通过interposer高速互连减少/取消器件之间的wire bonds，目的就是改善RF性能。citeturn945735search6turn945735search9

第三，**把光学组装变得更像半导体组装**。也就是：

\[
\text{manual optical assembly}
\]

变成尽可能多的：

\[
\boxed{\text{wafer-level + pick-and-place + passive alignment}}
\]

POET明确把wafer-level bonding/testing、known-good die和passive alignment作为降低BOM、assembly、test和CAPEX的核心手段。citeturn945735search1

所以POET真正解决的是：

\[
\boxed{
\text{Photonic Packaging Complexity}
}
\]

而不是：

\[
\text{Laser Performance}
\]

你甚至可以把它和我们之前几条路线放在一起：

| 技术 | 解决什么问题 |
|---|---|
| **EML** | 高速光怎么产生和调制 |
| **SiPh modulator** | 光怎么高速调制并在PIC里集成 |
| **DSP/LPO** | 高速电信号怎么处理 |
| **CPO** | optics应该离ASIC多近 |
| **POET** | **这些光电器件怎么高密度、低成本地装在一起** |

而为什么800G→1.6T→3.2T以后POET这种技术理论上更有价值？因为：

\[
Lane\ Rate↑
\]

导致：

\[
RF\ tolerance↓
\]

同时：

\[
Channel\ Count↑
\]

导致：

\[
Optical\ assembly\ complexity↑
\]

于是传统：

**wire bond + active alignment + discrete assembly**

越来越难。

POET赌的是：

\[
\boxed{
高速越高、集成越复杂
\Rightarrow
光子封装必须越来越“半导体化”
}
\]

这其实就是它最核心的技术逻辑。

但这也立刻告诉我们**下一步该验证什么**：不是继续听POET说“interposer很好”，而是查它相对于传统SiPh/传统光模块封装，究竟能把 **alignment cost、coupling loss、RF loss、engine size、yield、assembly time** 改善多少。这几个数字如果没有明显优势，POET的故事就弱；如果有明显优势，才是真正的技术壁垒。

Coherent现在已经展示400G/lane的D-EML和SiPh链路，用于未来3.2T pluggable；OIF也已经进入224G/448G electrical interface和co-packaging工作阶段。citeturn563385search4turn563385search9

所以我会把制造变化总结成一句：

\[
\boxed{

\rightarrow

\rightarrow

# 一、先看传统800G制造流程

以比较典型的EML/SiPh pluggable为例，大致是：

```text
        ↓
```

# 二、第一大变化：普通Die Attach → 超高精度Die Attach

这个变化我认为非常确定。

100G/lane时代，器件之间位置误差还有比较大的engineering margin。

到了：

\[
200G \rightarrow 400G/lane
\]

如果你做：

- EML + Driver
- CW laser + SiPh
- PD + TIA
- chiplet + interposer

器件必须越来越靠近。

原因不仅是光学，而是RF。

例如：

```text
Driver ───── EML
```

距离越长：

- parasitic inductance ↑
- capacitance ↑
- RF loss ↑
- impedance discontinuity ↑

所以越来越希望：

```text
Driver ↔ EML
```

做到非常短。

这意味着设备需求从：

> “我能不能把die放上去”

变成：

> **“我能不能以µm甚至更高精度、高throughput、低tilt地把多个异质die放到同一平台上。”**

### 因此受益：

\[
\boxed{\text{High-precision die bonder}}
\]

以及：

- flip-chip bonder
- hybrid integration设备
- chiplet placement
- advanced die attach

**设备价值量：↑↑**

### RF-grade / ultra-short interconnect

要求：

\[
\boxed{\uparrow}

同时价值会向：

- flip-chip
- Cu pillar/bump

转移。

# 四、Active Alignment：这是最值得研究的变化之一

传统光学：

```text

   ↓

   ↓

   ↓

   ↓
固定
```

这是：

\[

过去它为什么有价值？

因为：

alignment tolerance非常小。

所以需要昂贵的：

- 六轴stage
- optical power feedback
- vision
- active alignment algorithm
- dispense/cure

\[

- link budget越来越紧

> **哪一种1.6T/3.2T封装路线获得份额？**

# 第一类：基本属于事实

例如：

> lane rate从100G→200G→400G，PCB越来越难。

这个不是假设。

因为这是高速信号物理。

Insertion Loss

Reflection

Crosstalk

Nyquist frequency

这些都是物理规律。

因此：

> electrical reach越来越短

属于：

> **Physics**

不是投资判断。

---

例如：

DSP功耗越来越高。

也是事实。

因为：

224G SerDes

DSP复杂度

ADC/DAC

这些都有公开数据。

---

所以：

这一部分没有问题。

---

# 第二类：行业共识，但不是事实

例如：

我们一直说：

> CPO越来越重要。

这里其实有一个隐藏假设。

真正成立的是：

```text
200G/lane

↓

Pluggable越来越困难
```

这是事实。

但是：

```text
↓

一定进入CPO
```

不是事实。

因为还有：

NPO

LPO

更好的PCB

更好的SerDes

更好的Connector

甚至：

继续Pluggable

都有可能。

事实上，Cignal AI最近的观点也比较谨慎：他们认为**CPO部署正在加速，但短期对Pluggable影响有限，未来几年两者会长期共存**。citeturn0search0turn0search10

所以更严谨应该说：

> **Electrical reach缩短，提高了CPO的相对价值。**

而不是：

> **一定进入CPO。**

# 第三类：SiPh价值提高

这里我前面说：

> 通道越多，SiPh价值越高。

严格来说：

这是：

**Engineering Logic**

不是：

Market Fact

因为还有另一条路线：

InP PIC

Hybrid PIC

POET

等等。

真正成立的是：

> **光子集成的重要性提高。**

至于：

Silicon Photonics

获胜。

所以以后应该改成：

```text
SiPh受益
```

而不是：

```text

↓

```

# 第四类：POET

这里我认为是我们讨论里最大的假设。

例如：


注意：

这里有：

**If**

而不是：

这是投资最重要的区别。

# 第五类：设备价值量

这里其实也有。

例如：

我们说：

```text
Fiber Attach

↑↑
```

其实真正应该说：

```text
如果：

Photonic Integration↑

那么：

Fiber Attach的重要性提高。
```

为什么？

因为还有一种可能：

未来：

Fiber Array

直接标准化。

Automation做好。

所以：

不能说：

只能说：

对应工序的重要性提高。

至于：

价值量是不是提高。

Automation

# 第六类：Active Alignment设备

这是我觉得我们推论最危险的地方。

我们后来说：

> POET减少Active Alignment。

这里其实有两个假设。

第一：

POET成功。

第二：

POET份额足够大。

否则：

整个市场：

仍然：

Active Alignment增长。

所以：

真正应该写：

```text
如果：

Passive Alignment路线获得份额

↓

Active Alignment需求占比下降。
```

不是：

一定下降。

# 第七类：价值量迁移

这里其实也有。

例如：

我们说：

```text
PCB价值下降

Packaging价值上升
```

其实：

价值量迁移，

需要三个条件：

第一：

技术迁移。

第二：

客户采用。

第三：

供应链ASP提升。

否则：

可能：

价值没有迁移。

只是：

利润率迁移。

甚至：

价格竞争。

# 我认为最大的一个"偷换"

其实不是技术。

而是：

我们后来越来越喜欢说：

```text
A解决问题

↓

价值量提升
```

实际上：

这里缺了一步。

真正应该是：

```text
A解决问题

↓

客户采用

↓

市场份额提高

↓

ASP稳定

↓

利润提高

↓

价值量提高
```

中间：

至少四步。

不能直接跳。
