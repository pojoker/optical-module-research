# 以零件和路线聚合本地知识

**更新讨论稿｜2026-09-07｜供用户与 Kimi 共议**

本稿已按用户最新意见整体更新，沿用原文件路径方便转发。原“问题—具体对象—证据—解释”稿中的主动补研究、选样机重建答案方向，不再作为本次方案。

## 1. 目标

**保留对话形成的问答网页，以其中的零件和路线为入口，聚合本地已有数据与知识，让抽象讲解旁边出现现实资料。**

用户希望保留国内与海外公司知识库、学习网页，以及Codex/Kimi设计任务、其他执行者完成任务、再审阅整合的工作方式。现在要做的是把已有成果用起来：读到一个零件或路线，可以看到本地掌握的定义、产品、公司披露、工艺与来源。

不要求公司披露证明整段GPT回答，也不把所有零件拼成一只真实模块。GPT问答提供阅读入口，聚合内容以本地资料为准。

## 2. 聚合什么

| 对象 | 可聚合的内容 | 关联条件 |
|---|---|---|
| **零件**，例如激光器、PD、TIA | 本地已有的定义、功能、规格、材料、制造工序、产品及公司披露 | 材料明确涉及该零件；保留型号、用途、日期和披露范围 |
| **路线** | 本地已有的路线定义、适用对象、组件配置、接口、工艺与产品实例 | 材料明确描述该路线或关联；不同对象的资料不能拼成完整路线 |

公司信息是聚合内容的一部分，不是唯一中心。应说明该公司是做器件、使用设备、制造设备，还是披露产品进展；资料没有说清角色时，不替它判断。

路线名词可能属于不同维度。本地资料如何界定，就如何保留；不同维度可以分别展示，不能因为名词在问答里并列出现，就将它们整理为互斥选项。

## 3. 资料从哪里来，允许怎样处理

只使用当前本地、已授权读取的账本、知识条目及原始材料，例如根级公司能力和知识账本、海外calls账本、已保存的年报、招股书、技术资料与标准快照。旧分支和禁读归档不因本方案自动获得读取许可。

允许做：**摘录、忠实转述、归类、去重、标注来源与范围。** 不新增推论。

具体约束：

- 每项内容都能回到本地文件及条目ID、页码或章节；已有原始URL一并保留。
- 零件属于哪种路线、公司与产品有什么关系，只在材料明确记载时建立关联。
- 同一来源的重复转载合并展示，不能算成多份独立证据；不同来源相似表述保留各自身份。
- 来源发生冲突或属于不同日期/型号时，分别展示差异，不自行综合出“正确版本”。
- 本地知识原本是派生、候选或UNKNOWN的，必须保留其身份；“存在本地”不等于“已经证实”。已有推论不能改写为事实，也不继续推导新结论。
- 没有材料时显示“暂无本地材料”，不写成“行业不存在”，不启动外部补研究。
- 对话中的教学假设及后续纠错不应被聚合资料掩盖；某个实例与正文相关，不代表整段正文均获证实。

## 4. 页面上呈现什么

读者可以从问答中零件或路线的名称进入，先看到一条简短资料，再展开更多内容。首次试做沿用现有网页，不另建一套产品。

每组内容最少回答四个问题：

| 读者想知道 | 展示内容 |
|---|---|
| 本地掌握了什么？ | 对该零件或路线的原文摘录/忠实摘要 |
| 是谁、哪个对象的资料？ | 公司、产品或规范名称，以及日期、型号或版本 |
| 资料是什么身份？ | 公司披露、规范描述、既有派生、候选等；不混为同等确定性 |
| 去哪里核对？ | 本地条目及原文定位、已有来源链接 |

例如，问答提到“激光器芯片”，可聚合本地已有的相关公司能力条目、KN005中的仕佳DFB工艺实例及原文定位。它们分别说明各自对象，不由此推断某款800G模块使用了谁的芯片。

问答提到某条路线时，只收进本地明确归属于它的资料。没有对应材料的组件配置就留空，不依靠模型知识补一张看似完整的BOM。以上是组织方式示例，并非已经完成的聚合结果。

## 5. 如何做一次小范围试做

先在当前页面选少量零件和一个路线入口，按本地资料可用性确定试做对象，不预设必须填满哪些栏目。

1. 列出页面中的对象名称，在允许的本地材料中查找明确对应的条目。
2. 摘出相关内容，保留来源、对象范围和原有知识身份；无法明确关联的暂不归入。
3. 将重复资料整理成简短可读的内容，并提供展开入口。
4. 审阅是否忠于原文、是否误归类、是否新增推论；再由用户看阅读效果。

如后续启用多执行者，任务应是“整理指定对象的本地材料”，而不是“研究该对象并给出完整答案”。每人有明确读取范围；交付可核对的摘录与定位，审阅后再整合。

**验收只看：内容是否来自本地、归类是否有依据、来源能否定位、是否保持原有范围和身份、阅读是否更有帮助。** 不以填满栏目、关联公司数量或页面变长作为成功标准。
