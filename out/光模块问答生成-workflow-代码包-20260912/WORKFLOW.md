# 光模块问答生成与阅读器发布 Workflow

版本：2026-09-12  
适用项目：optical-module-research

## 先说结论

当前这套成果不是“把一段提示词交给模型，就自动生成一套可信网页”。实际链路是：

> 原始 GPT 问答归档 → 提炼问题与理解顺序 → 选择具体参考对象 → 按因果链补证据 → 写研究稿 → 人工整理页面 → 静态构建 → 机器校验 → 人工复核 → 用户授权后发布

其中，原始 GPT 问答主要提供“要问什么”和“读者卡在哪里”，不自动充当技术事实证据。网页中的事实、推论、候选和 UNKNOWN 必须保持边界。

当前有两种读者形态：

1. **连续问答页**：site/optical-qa/index.html。14 个连续问题合并为一条阅读路径，当前是已整理好的静态 HTML，没有独立的问答自动生成器。
2. **模块化读者站**：site/optical-module/。由 tools/site/build_optical_module_site.py 读取页面配置和 HTML 片段，生成 9 页、27 个 section 的站点到 out/光模块知识体系/。

因此，本包包含了“内容怎样形成”和“页面怎样构建”的现有代码；不把不存在的自动生成能力包装成已经完成。

## 1. 目标、输入和输出

### 目标

以三段原始 GPT 问答为起点，先让读者沿着一个真实的光信号路径读懂：

> 光模块完成什么功能 → 由什么功能/组件实现 → 组件怎样衔接 → 零件怎样制造 → 模块怎样装配与测试 → 速率和技术路线改变了什么

内容先独立成型；只有当具体节点成熟后，才选择性关联原有国内/海外知识库。

### 输入

- 三段完整 GPT 对话：40 轮、82 条消息。
- 原始问题中反复出现的组成、连接、制造、测试、速率升级、EML/SiPh/VCSEL、LPO/CPO、POET 和投资推论。
- 产品规格书、器件说明、工艺论文、标准/规范和厂商公开资料。
- 后续才使用的本地 canonical 账本或公司材料；它们不是第一阶段的组织骨架。

### 输出

- 研究稿：24 问扩充稿和 Driver → EML → 光耦合 → 光纤接口深读稿。
- 连续问答读者页：14 个问题，保留原始提问去向。
- 模块化读者站：总览 + 8 个主题页。
- 构建清单：页数、section 数、资源版本和 canonical_write: false。

## 2. 证据和状态的分层

| 层 | 内容 | 允许做什么 | 不允许做什么 |
|---|---|---|---|
| 原始语料 | 三段 GPT 对话及其 raw JSON | 提供问题、疑问和学习顺序 | 直接当作技术事实 |
| 研究稿 | 对问题的资料整理、解释和边界 | 形成候选答案、列出来源和 UNKNOWN | 自动写入 canonical |
| 事实 | 指定来源直接支持的对象、参数或工艺 | 按来源范围展示 | 外推到未披露产品或行业普遍规律 |
| 派生 | 从事实明确推出来的解释 | 写出推导条件 | 隐去推导过程后冒充原文 |
| 候选 | 值得继续核验的路线、能力或关系 | 保留在研究材料和候选展示中 | 未经人工和用户授权晋升 |
| UNKNOWN | 当前证据没有回答的内容 | 明确说明缺什么 | 用“通常”“大概”掩盖缺口 |
| 页面输出 | HTML/CSS/JS/SVG | 作为读者投影和共享快照 | 反向作为事实源回写 |
| canonical | knowledge.yaml 等正式账本 | 只在明确授权、证据闭合后写入 | 因构建成功、引用变多或页面发布而自动改变 |

机器门只检查结构、链接、引用形式和 canonical 是否被意外改写；“领域问题是否已经回答”仍由人工复核判定。

## 3. 当前问答形成的具体步骤

### Step 0：先锁定范围

新任务先读取：

- AGENTS.md
- docs/control/PROJECT_CHARTER.md
- docs/control/ACTIVE_WORKPACK.yaml

确认北极星、允许写入路径、非目标和验收条件。当前读者任务的关键非目标是：不把问答扩展直接变成完整产业链供货关系，不自动晋升 canonical，不把一个产品的内部结构外推成行业通用 BOM。

### Step 1：保存原始问答

三段原始对话保存到 docs/source-conversations/：

- 光模块技术需求.md：3 轮
- 光模块技术路线梳理.md：27 轮
- 光模块构成介绍1.md：10 轮

每段同时保留原始返回 JSON。先确认分页完整、轮 ID 无重复、Markdown 与 JSON 逐消息一致，再进入内容整理。原问答中的错误、假设和未经核验的结论保留原样，不因保存成功而成为事实。

### Step 2：从原问题建立读者路径

不按“资料能搜到什么”组织页面，而按“读者需要先理解什么”排序。重复问题合并，但保留原始问题的去向。

连续问答页的 14 题主线是：

1. 什么是光模块？
2. 光模块由什么构成？
3. 构件怎样衔接？
4. 零件怎样制造？
5. 模块怎样装配？
6. 装好后怎样评价？
7. 为什么从 800G 走向 1.6T/3.2T？
8. EML、SiPh、VCSEL、LPO、CPO 等路线怎样归位？
9. DSP、Driver、TIA、retimer 的电处理职责怎样分？
10. Front-panel、NPO、CPO 改变的是哪里？
11. lane rate 变高后，工序和约束怎样迁移？
12. 如何把 POET 这类公司/方案落到具体对象和工序？
13. 哪些投资判断只是技术假设，不能直接当证据？
14. 以后怎样继续提问，才能沿对象、接口、误差和测试追下去？

这 14 题不是自动状态机；归入某题只表示原问题找到了阅读位置，不表示其所有子问题已经解决。

### Step 3：固定一个具体参考对象

当前选择 Coherent FTCE4527E1PCA/FTCE4527E1PxA 系列 800G-DR8+ OSFP 作为接口和器件类型的参考对象，原因是公开规格相对明确。

它用于限定讨论范围，例如：

- EML 发射器、PIN 接收器、Dual MPO12 和 2 km 单模链路；
- 8×100G 级 PAM4 电接口、每 lane 106.25 Gb/s、3.3 V 和 I²C 管理接口。

它不用于证明：

- 该产品的完整内部 BOM；
- 所有模块都采用相同器件或封装；
- 某个公司拥有该产品的供应关系；
- 800G/1.6T/3.2T 的行业普遍工艺、良率或设备价值。

### Step 4：用一条物理路径串起答案

先画功能路径，再逐个追接口、工序和测试：

    发射：主机电接口 → 信号处理 → Driver → EML 中的 EAM → 光耦合 → 光纤
    光源：供电 → EML 中的 DFB 激光器 ───────────────↑
    接收：光纤 → 光耦合 → PIN/PD → TIA → 信号处理 → 主机电接口

每个箭头都继续问四件事：

1. 两端连接的具体对象是什么？
2. 需要建立什么电、光、机械或热边界？
3. 哪种误差会造成什么失效？
4. 哪项测量能发现该失效？

这样避免把“有一个连接”直接写成“需要某一台设备”，也避免把典型架构拼成某只产品的已知 BOM。

### Step 5：按来源对象补证据

研究时先找能直接支持当前句子的来源，再写答案。来源要记录对象、定位、日期和适用范围。

证据使用顺序：

1. 产品规格书：确认具体产品公开的接口、器件类型和参数。
2. 标准/规范：确认接口、封装或路线定义。
3. 器件厂商资料：解释 EML、PD、TIA、PIC 等对象的功能，但限定为该厂商/器件说明。
4. 工艺论文或设备资料：解释某个器件或工序如何制造，不自动迁移到现代参考模块。
5. 厂商演示或新闻稿：记录“已演示/已宣布/计划”等状态，不改写成量产或市场份额。

同一家公司的一篇原文和基于它生成的摘要属于同一证据链，不算两份独立验证。网页能打开、引用编号能对上，也不等于结论已经完成语义复核。

### Step 6：写成“事实 → 解释 → 边界 → 下一问”

每题采用同一答案结构：

- 先给读者一个可以直接理解的短答案；
- 用一个具体对象或信号路径解释“为什么”；
- 明确哪些是来源直接披露、哪些是条件推论；
- 把未获得产品级证据的内容写为 UNKNOWN；
- 说明下一题为什么自然接上。

例如，Driver → EML → 光耦合 → 光纤不能只写成四个名词。当前稿将它拆成：

- Driver 到 EML：电驱动职责已能解释，但参考模块内部连接剖面尚未公开；
- EML 到耦合结构：需要把光从器件有效区域送到波导/光纤，不能直接把箭头等同于主动对准设备；
- 光路到光纤：FAU、SSC、edge/grating coupler 和固定方式需要分别核验；
- 装配之后：几何位置、耦合损耗、电性能和端到端误码各有测试对象，不能相互替代。

### Step 7：把路线变化写成约束迁移

路线比较不做简单的“谁先进、谁受益”排名，而按下面的因果链：

    系统需求/带宽增长
      → 电通道损耗、端口密度、功耗和热约束
      → DSP/Driver/TIA、PCB、连接器和光学位置的责任变化
      → EML、SiPh、VCSEL、LPO、NPO、CPO 的工程选择
      → 新的耦合、封装、散热、维修和测试问题

“工序变难”不能直接推出“设备价值量增加”。还需要目标产量、节拍、并行度、稼动率、良率、共用设备、售价和供应商份额等数据。

### Step 8：知识库关联后置

只有当一个页面节点已经讲清楚具体对象和机制，才检查本地材料是否有同名或同对象证据：

- 具名器件/工艺/路线被来源明确支持，才建立有限关联；
- 公司“具备某能力”不自动证明其供应某模块、采用某路线或拥有客户份额；
- 没有合适材料时显示“暂无本地材料”；
- 不为了填满页面而把多个公司的能力拼成一只虚拟模块。

### Step 9：写入页面源文件

模块化站点的内容分为：

- site/optical-module/pages.yaml：页面、导航、section 和顺序；
- site/optical-module/sections/*.html：读者可见内容片段；
- site/optical-module/templates/page.html：公共页面壳；
- site/optical-module/assets/：样式、脚本和解释图；
- site/optical-qa/index.html：14 题连续问答的当前静态整合页。

当前页面源是人工整理后的 HTML 片段，不是由原始对话直接拼接生成。修改事实内容时，应先修改受授权的研究/事实源，再更新页面投影；不能把构建后的 out/ 页面当作 canonical。

### Step 10：构建和校验

统一使用项目解释器：

    /Users/jowang/miniconda3/bin/python3 tools/site/build_optical_module_site.py

构建器会：

- 读取 pages.yaml 和 section 片段；
- 生成总览和 8 个模块页；
- 复制 CSS、JS、SVG；
- 生成 out/光模块知识体系/build-manifest.yaml；
- 在构建前后比较 knowledge.yaml SHA-256；
- 若 canonical 被读者构建意外改写则失败。

当前已验证的机器结果：

- 构建结果：PASS
- 输出：out/光模块知识体系/
- canonical_unchanged: true
- 清单：9 页、27 个 section、reader-only build。

测试入口：

    /Users/jowang/miniconda3/bin/python3 tests/site/test_optical_module_reader.py

当前测试事实要如实保留：直接运行共 18 项，17 项通过，1 项失败；失败是当前测试契约与页面现状不一致：

- 基础页测试仍要求至少 8 张远程图片，当前页面使用本地解释图，因此得到 0 张远程图片；

使用 pytest 收集该文件还会遇到 tests/site 与 Python 标准库 site 名称冲突，报 site is not a package。这个问题属于待修复的测试/页面契约，不应在交接时写成“全绿”。

## 4. 当前状态和下一步

### 已有

- 原始问答本地保存、逐轮 Markdown、raw JSON、索引和 SHA-256；
- 24 问扩充稿，覆盖零件、制造、装配、测试和路线；
- Driver → EML → 光耦合 → 光纤深读稿；

- 9 页/27 section 模块化读者站及其构建器；
- 机器构建能够确认 reader-only 且 canonical 未被改写。

### 尚未完成

- “约束 → 误差 → 失效 → 测试”的整条因果链还没有完全闭合；
- Driver 到 EML 的连接剖面、EML 到光路的定位、出纤固定和量产测试缺少足够的产品级证据；
- 研究稿尚未整体写入 canonical；
- 当前工作未宣称行业研究穷尽、量产状态完成或设备商业收益成立；
- 页面/测试对远程图和实际图引用数量的契约尚未统一；
- 14 题连续页目前没有独立可重复的内容生成器。

### 推荐执行顺序

1. 选定一个仍可取得资料的真实器件或发射 PIC，补齐一条可核验的接口剖面；
2. 对 Driver → EML → 耦合 → 光纤逐段补“对象—误差—失效—测试”；
3. 做一次段落级来源审计，检查每个主张的直接来源和适用边界；
4. 由用户审阅研究稿，决定哪些结论可以进入 canonical；
5. 再决定是否把 14 题连续页抽象成可维护的数据/模板生成器；
6. 测试契约与页面实际资源数量统一后，再进行正式发布。

## 5. 与其他问答采集代码的边界

项目中的 corpus/_fetch_qa.py、domestic_daily/ 和 calls/ 是另一条“国内互动问答/海外情报日更”链路：

> 公开端点采集 → 外部状态目录 → 候选/失败保留 → 日报组装

它们不负责把三段 GPT 问答写成当前读者页，也不自动晋升光模块研究结论。本包没有把这两条链路混为一谈；如需单独交接日更采集，再提供独立代码包。
